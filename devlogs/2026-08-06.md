# 2026-08-06

## Repo moved, game renamed to Nuclear Rush

- The GitHub repo was renamed twice today (`chatgtt` -> `swing-or-get-swung`
  -> `Nuclear-Rush`); it's the same repo throughout (same ID, same PR #1),
  just a naming decision settling.
- The game itself is now officially named **Nuclear Rush**.

## Lean removed, teams renamed to RED/BLUE

- Removed the lean mechanic entirely: input action, HUD lean buttons and
  settings chips, camera/gun/body tilt math, and the network protocol
  field. Left `riftline_map.gd`'s unrelated `_build_stormgate(..., lean:
  float)` architecture-tilt parameter alone - different thing, same word.
- Renamed the team enum and every reference from SUN/VOID to RED/BLUE:
  scripts, HUD labels, network wire fields, landmark node names
  (SunDock/VoidDock -> RedDock/BlueDock). Also fixed team accent colors
  that were still rendering orange for "RED" (leftover from the old SUN
  palette) - RED now actually renders red.
- Verified with a clean headless import and all 14 exercise scripts
  passing.

## Final game design decision recorded

- See `handoffs/DESIGN-nuclear-rush.md` for the full, final mode design:
  continuous 4v4, 10-minute match, no round resets, one neutral core
  spawns center-map, teams carry it back to their **own** base (not the
  enemy's) to start a launch countdown, the opposing team can cancel it,
  first to 3 points wins (sudden death on a tie at time expiry).
- This is now the only game mode. It supersedes the enemy-base-delivery
  "Nuke Rush" mode implemented on PR #1's `circular-nuke-arena` branch -
  that PR's win condition now conflicts with the final design and needs
  rework before merge. Left a note on the PR and in `HANDOFF.md`.
- Team roles (Shield Operator, Core Carrier, Support Operator, Observer/
  Marksman) and several implementation details (exact carrier penalty,
  whether roles are hard-enforced loadout classes, countdown duration,
  cancel interaction) are recorded as open questions in the design doc,
  not yet decided.

## Robert: circular Nuke Rush arena (PR #1, `circular-nuke-arena`)

Recorded from the PR branch when it was merged on 2026-08-07.
The layout below is what shipped; the mode rules described here were superseded that same day by `handoffs/DESIGN-nuclear-rush.md` (own-base delivery, not enemy-base) - see `devlogs/2026-08-07.md`.


## Circular Nuke Rush arena

- Rebuilt Concourse as a symmetric circular 5v5 arena with opposing SUN and
  VOID bases, five spawn positions per side, circular flank routes, and a
  central procedural nuke pickup room.
- Added Nuke Rush as a complete match mode: neutral center pickup, carried and
  dropped states, steals by either team, immediate victory at the enemy base,
  and timeout victory based on each team's furthest push. Exact ties receive a
  30-second overtime.
- Added replicated objective state, protocol version 10 support, HUD timer and
  progress indicators, objective callouts, practice-mode selection, and a
  procedural `pulp_lit` nuke model. No imported art or textures were added.
- Extended the map and mode exercise coverage for layout, landmark, pickup,
  drop, steal, delivery, timeout, and network descriptor behavior.
- Verified with the serial headless import and every `tools/*_exercise.gd`
  runner; all passed. Also visually checked overview, pickup-room, and live 5v5
  captures, then ran a concurrent LAN host/join smoke test. The only network
  diagnostic was the already documented ENet MTU warning.
- Device deployment and touch playtesting were not performed in this session.

## Nuke Rush 4v4 follow-up

- Revised the mode from five to four players per team. Concourse now exposes
  four symmetric spawn slots at each base, and Full Line offline practice
  launches four teammates per side.
- Nuke Rush LAN configuration and received session descriptors are normalized
  to 4v4, while other modes retain their existing supported team sizes.
- Updated the practice-mode copy, formation diagram, exercise expectations,
  handoff, and pull-request description to match the new player count.
- Added `nuke_rush_arena.tscn` as the canonical Concourse scene used by the
  game. Its `RiftlineMap` child builds the same procedural geometry in the
  Godot editor, so the full circular map is visible when the scene is opened.

## Layered cover and terrain pass

- Used the supplied competitive arena FPS clip as a structural reference for
  denser cover, short sightlines, indoor/outdoor transitions, and traversable
  verticality; no video assets, textures, or external meshes were imported.
- Added mirrored north/south midfield decks with two side ramps each and a
  playable lower route, plus roofed east/west flank corridors, four L-shaped
  hard corners, and staggered waist-high cover on both base approaches.
- Expanded the authored route graph with center-room entrance nodes and
  corridor entrance/exit nodes so all four spawns and tactical lane posts can
  still reach the nuke and opposing base.
- Added named procedural terrain nodes and preview cameras for the decks and
  west underpass, and extended the map exercise to lock the new cover density
  and landmarks.
- Visually checked overview, deck, underpass, and live 4v4 captures. The full
  exercise suite passed, and a desktop Forward Mobile sample held 8.33 ms per
  frame over 120 frames (the project's 120 FPS target).

## Diagram-matched cover layout

- Replaced the scattered L-shaped and base-approach cover with the supplied
  top-down arrangement while retaining the traversable decks, ramps, and
  roofed flank corridors.
- Added four rectangular cover columns on each side, four inset shoulder
  blocks, paired north/south base cover, and two rows of three low circular
  covers around the central nuke room.
- Shifted the circular rows slightly away from the pickup-room doors to retain
  player clearance, then added symmetric gap, threshold, and corridor-exit
  route nodes so bots can use every lane without oscillating.
- Verified the arrangement with top-down, center-room, and live 4v4 captures;
  headless import and the complete exercise suite pass.
